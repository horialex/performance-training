# User Jurneys:
We tried to cover the most important and used jurneys that a user usually does in this application. 
Using a Throughtput controller we distributed the load on these jurneys based on the frequency that they happen.
* The way we choose to distribute the frequency of these jurneys in our runs is either by using commons sense, 
discussing with the client or by looking at the logs they collect from the real application.
In this case we used the common sense since we had no inforamtion about the other ways to do this.

Frequency distribution
0. Login -                        - 100% in case of  Logged in Thread Group 
1. Explore application / products - 50%
2. Search 			  - 30%
3. Add to cart                    - 20%
4. Update cart                    - 7%


# User think time simulation (wait time)
We can't do a proper load testing withut taking into consideration the user think time, we don't want to just bombard the 
server with requests but we want to simulate a real life situation as close as possible.
This can be customized from otuside the script
We had 3 types of user pause, short, medium and long and we have put them between the requests based on how much a real user 
would think and pause between his actions:

WAIT_TIME_SHORT  = 1000 (1 second)
WAIT_TIME_MID    = 3000 (3 seconds)
WAIT_TIME_LONG   = 5000 (5 seconds)
